Privacy

This page describes what holidaychasers.ie actually does when you browse it. It is written from the site’s own pages and scripts.

Holiday Chasers is a fare-finding and trip-planning site for travellers anywhere in Ireland. The airports it searches from are Cork and Dublin, the two biggest airports. There is no account, and the site does not take a booking or a card payment.

Hosting

The site is static HTML, CSS, JavaScript and images, published with GitHub Pages. The repository’s CNAME file points the site at holidaychasers.ie. GitHub serves the files. This repository does not show what GitHub logs, or for how long.

Analytics, and the consent banner

A shared script, /consent.js, is loaded by the homepage, the destination pages, and these information pages. It does not load analytics until you choose.

  • If you press “That’s fine”, the script stores hc_consent as yes in the browser’s localStorage and loads Google Analytics 4.
  • If you press “No thanks”, it stores hc_consent as no and does not load the tag.
  • If you have not chosen, the tag is not loaded. The banner is shown.
  • Once a choice is stored, the banner is not shown again.

The measurement ID is G-ZL57HH33JG. The tag script is requested from https://www.googletagmanager.com/gtag/js?id=G-ZL57HH33JG. It is loaded only when the hostname in the address bar is exactly holidaychasers.ie. On any other host, including a local copy, the tag is not loaded.

The tag is configured with anonymize_ip set to true. The script does not set a user id, an ads flag, or a cookie lifetime. It also does not switch off the tag’s usual page-view hit. This site does not include a Google Tag Manager container or a Meta Pixel.

The site’s own scripts never write a cookie. After you accept, the Google tag runs, and that tag uses cookies. The cookie names and how long they last are not set in this repository.

Events sent to analytics

Custom events are sent only after the tag has loaded, which means you accepted and you are on holidaychasers.ie. The event names in the scripts are:

  • flight_click — a booking or compare link. The homepage can include a source (where on the page) and a destination code. A destination page can include the city name, the airport code, the source destination_page, and the first 40 characters of the link text. An origin airport is included only when the link carries one.
  • stay_click — a hotel link, with the city and a short label.
  • trip_calc_click — a row in the trip-cost list, with the city and a short label.
  • restaurant_click — a restaurant row, with the city and a short label.
  • newsletter_signup — sent with the location homepage after the signup request succeeds.
  • view_destination — opening a trip guide. Parameters can include the city, the origin airport (Cork or Dublin), or a source and a destination code.

Newsletter

The homepage has one signup form. It sends the email address you type to MailerLite, by posting the form to:

https://assets.mailerlite.com/jsonp/2462970/forms/190982595838739584/subscribe

The fields sent are the email (fields[email]), plus ml-submit and anticsrf. The page tries that post from the browser. If the post fails, the form is submitted in a new tab instead. Nothing else from the form is sent.

What MailerLite does with the address after it arrives — including how long it is kept, and how to unsubscribe — is not in this website’s code. This site has no unsubscribe page. To ask about a signup, email info@holidaychasers.ie.

What stays in your browser

Besides the analytics choice, the homepage script can store these localStorage values on your device. They are not posted to Holiday Chasers as a form.

  • hc_favs — destination codes and city names you save with the heart button.
  • hc_wx2_ followed by an airport code and a date — a cached weather result for that city and date, so the board does not ask again on every visit.
  • hc_rest2_ followed by an airport code — a cached restaurant list, kept for 7 days.
  • hc_attr_ followed by an airport code — a cached attraction list, kept for 7 days.
  • hc_backend — a function in the script can save a server address under this key. The published pages do not show a control that runs it, and the live-search address the site uses is written in the script, not read from this key.

Live search and other requests

The homepage asks a Cloudflare Worker at https://hc-live-search.djonov.workers.dev for a few things. The script does not add your name, email, or an account id. Like any web request, the worker sees the connection from your browser, including the IP address. What the worker logs, and for how long, is not in this repository.

  • GET /api/health — a short check, sent when the homepage loads, with no search details.
  • POST /api/search/direct — when a trip guide looks up live fares. The JSON body contains a destination airport code, an outbound date, a return date (often empty, because each leg is asked for on its own), and departure_override (the airport the leg starts from, Cork, Dublin, or the destination on the way back).
  • GET /api/events — city name and the start and end of the trip, for event listings. A comment in the script says this lets a Ticketmaster key stay on the worker. The worker’s code is not in this repository.
  • GET /api/places — kind=restaurant or kind=attraction, plus the city’s latitude and longitude, not your device’s location. A comment in the script says this lets a Google Places key stay on the worker.
  • GET /api/places/photo — a photo reference returned by the places call, and a width.

If an event listing includes an image address or a link, the browser then requests that address. Restaurant and attraction links are whatever URL the worker returned. Those hosts are not fixed in this repository.

The homepage also requests:

  • deals_cache.json on this site — the scanned fares.
  • Wikipedia at en.wikipedia.org (/api/rest_v1/page/summary/ and, for some photos, /api/rest_v1/page/media-list/) — a short city description and a photo. The browser then loads the image address Wikipedia returns.
  • Open-Meteo — api.open-meteo.com for a forecast, and archive-api.open-meteo.com for a typical past range. The coordinates and the date are the city’s, from the site’s own list. For a city that list does not cover, the guide asks geocoding-api.open-meteo.com with the city name.

Links that leave the site

Booking buttons open another site. The script builds the link from the trip you are looking at. It does not send your email with those links.

  • Ryanair — airports, dates, the number of adults and children selected on the page, and zeros for teens and infants.
  • Aer Lingus — the same kind of search: return or one-way, economy, adult and child counts, airports and dates.
  • Aviasales — origin, destination, dates, adult count, currency euros, locale English, and a fixed partner marker (marker=543929). The child count is not added to this link.
  • Booking.com and Airbnb — city, dates, and the adult and child counts. On Booking.com each child is sent with an age of 8, which is a fixed value in the script, not an age you entered. An affiliate id is added only if one is filled in. In the current script that id is empty.
  • DiscoverCars, Rentalcars.com and Auto Europe — city and dates. An affiliate parameter is added only if a code is filled in. Those codes are empty in the current script.
  • Welcome Pickups — the city name, for a taxi or transfer row. A referral code is added only if one is set. It is empty in the current script.
  • Other getting-around rows open a transport site stored for that city, when the guide has one.
  • Some map and restaurant fallbacks open Google Maps at the city’s coordinates.
  • The footer links to Facebook and Instagram.

Fonts

The homepage and these information pages load Fraunces, Inter and JetBrains Mono from Google Fonts (fonts.googleapis.com and fonts.gstatic.com). Destination fare pages use a font already on your device and do not request Google Fonts. Logos, the fare file and /consent.js are loaded from this site.

Changing your analytics choice

There is no control on the site to change the choice after you make it. To withdraw it, clear this site’s stored data in your browser (site data for holidaychasers.ie, which covers the hc_consent value and any cookies the Google tag has set). On the next visit the banner is shown again. Choose “No thanks” and the tag stays unloaded.

Clearing site data also removes saved destinations and the cached weather, restaurant and attraction lists.
